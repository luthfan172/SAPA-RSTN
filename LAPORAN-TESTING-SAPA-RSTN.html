3. Daftar Temuan Terperinci (Security & Functional Findings)

A. Temuan Keamanan (Security Vulnerabilities)

Tinggi SEC-01: Potensi Stored XSS via Direktif v-html pada Artikel Edukasi
EdukasiDetailView.vue:L91
Konten artikel kesehatan dirender langsung menggunakan v-html="artikel.isi || 'Belum ada konten'". Jika data API dari backend atau database disusupi payload HTML berbahaya (misal <img src=x onerror=...>), kode JavaScript tak berizin akan tereksekusi di browser pasien dengan hak akses penuh ke LocalStorage portal.
Rekomendasi Perbaikan: Pasang pustaka dompurify dan bungkus sebelum dirender: const cleanContent = computed(() => DOMPurify.sanitize(artikel.value?.isi || '')).
Sedang SEC-02: Reverse Tabnabbing via window.open Tanpa noopener,noreferrer
PreviewDokumenView.vue:L279
Pada penanganan unduh PDF untuk perangkat iOS, tab baru dibuka dengan window.open(url, '_blank') tanpa parameter rel. Halaman yang dibuka memiliki akses ke window.opener dan berpotensi memanipulasi tab asal pasien.
Rekomendasi Perbaikan: Gunakan parameter ketiga: window.open(url, '_blank', 'noopener,noreferrer').
Sedang SEC-03: Hardcoded Base URL Gambar Menggunakan Plain HTTP dan IP Publik
src/utils/edukasi.js:L8
Base URL didefinisikan sebagai http://194.169.46.193/gos2_plus/uploads/edukasi/. Saat portal di-hosting pada HTTPS, peramban modern akan memblokir gambar tersebut akibat Mixed Content Policy, serta mengekspos IP server internal.
Rekomendasi Perbaikan: Pindahkan ke environment variable import.meta.env.VITE_EDUKASI_IMG_BASE dengan fallback domain resmi https://apirstjokro.purworejokab.go.id/....
Sedang SEC-04: Kredensial Firebase Client Hardcoded dalam Source Code
src/services/firebase.js:L5-13
Kredensial Firebase (API Key, Project ID, App ID) tercantum statis di source code. Meskipun client-side config, best practice mewajibkan isolasi melalui variabel .env dan pembatasan domain di Google Cloud Console.
Rekomendasi Perbaikan: Gunakan import.meta.env.VITE_FIREBASE_* dan aktifkan HTTP Referrer Restrictions pada API Key.
Tinggi SEC-05: 12 Kerentanan Tingkat Tinggi pada Dependensi Pihak Ketiga
package.json (NPM Audit)
Audit dependensi menemukan 12 vulnerabilitas tingkat High pada paket @grpc/grpc-js (auth cert bypass), @vue/server-renderer (XSS), fast-uri (SSRF), follow-redirects (credential leak), source-map-js (DoS), dan vite/launch-editor (command execution).
Rekomendasi Perbaikan: Lakukan koordinasi pembaruan minor/patch pada Vite (>=8.2.3) dan patch paket Firebase.
Rendah SEC-06: Penyimpanan Token JWT dan Data Pasien Sensitif di LocalStorage
src/stores/auth.js:L35-36
sapa_token dan objek sapa_user (berisi NORM dan nama pasien) disimpan dalam LocalStorage yang rentan diekfiltrasi jika terjadi serangan XSS pada aplikasi.
Rekomendasi Perbaikan: Evaluasi penggunaan cookie HttpOnly; Secure; SameSite=Strict untuk token sesi.

B. Temuan Fungsional & Arsitektur

Sedang FUNC-01: Fitur Tandai Semua Dibaca Belum Terhubung ke Endpoint Server
src/stores/notification.js:L276
Fungsi markAllPersonalAsRead() hanya menandai status baca pada LocalStorage lokal browser tanpa mengirimkan request sinkronisasi ke server API SIMRS. Status unread akan muncul kembali bila pasien membuka perangkat lain.
Rekomendasi: Koordinasikan dengan backend untuk penyediaan endpoint POST /notifikasi/tandai-semua-dibaca.
Sedang FUNC-02: Inkonsistensi Dokumentasi Respons Rencana Kontrol BPJS Saat Nihil
src/views/RiwayatReservasiView.vue:L692
Bentuk payload SIMRS saat pasien tidak memiliki rencana kontrol belum didokumentasikan secara definitif (apakah data: null, data: [], atau kode HTTP selain 200).
Rekomendasi: Tetapkan kontrak API JSON formal dengan mentor SIMRS untuk skenario data kosong.
